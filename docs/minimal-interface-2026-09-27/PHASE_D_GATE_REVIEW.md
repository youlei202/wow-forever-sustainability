# Independent Phase D gate review

Recommendation: do not activate prospective native simulations in this round.
Phases A–B report PASS and the corrected Phase C implementation passes. That
satisfies the necessary correctness prerequisite. It does not by itself justify
new sampling. The remaining condition—whether additional independent native
breadth is sufficiently valuable—is a research judgement. On the current
evidence, completing the auditable account of the frozen data offers a clearer
increment than starting another search for an obstruction.

This is a recommendation for the integrating task, not an activation decision
or a prospective protocol. Phase D is `not_run`, not zero performance. No new
simulations or alpha allocation were requested or executed by this review.

## Evidence considered

The review uses the full five-page minimal-interface proof note, the newest
paper's model, theory, inference, main results, and detailed native-method and
native-result appendices; the current `native/NATIVE_SUMMARY.json`,
`native/TARGET_QUERY_EQUIVALENCE.json`, `native/MINIMAL_OBSTRUCTIONS.jsonl`,
the independent Druid recheck, and corrected `theory/v2/` results. Input hashes
are recorded in `checks/PHASE_D_GATE_REVIEW.json`.

All 184,320 target queries across 96 frozen contract variants were enumerated.
The exact, supported, and possible projected interfaces preserve their
respective target-query answers. The variants consist of 16 primary base
menus, eight nested expansions, eight task projections, and 64 tolerance
variants. They must not be counted as 96 independent native environments.
There are zero projection merges because the pre-existing arbitrary-in-menu
query universe is I minus H. Removing mandatory history labels can reduce
serialized bytes without reducing the number of stored maximal sets.

In the 16 primary base menus, order-1, order-2, and order-3 summaries miss
351, 3, and 0 certified negative decisions, respectively. Their descriptive
denominator is the 16,384 enumerated target queries. The corresponding
UNKNOWN-blocked counts are 974, 4, and 0; those cases are not certified misses.
The primary inventory contains 64 certified minimal obstructions: two empty
targets, 40 singletons, 20 pairs, and two triples. The two triples share one
Druid menu and the same frozen observations. No order-3 miss in this pool
does not establish a universal order-3 sufficiency theorem, nor does absence
of a larger certified obstruction rule out a true one hidden by UNKNOWN.

The named Druid triple reproduces independently: all three pairs are YES,

## Why another campaign is not presently the priority

The new proof settles the abstract arbitrary-order question without native
replication. The original native triple already links the representation issue
to measured legacy retention; the independent reconstruction strengthens its
auditability. The exhaustive ablation now quantifies what lower-order summaries
lose and what they do not lose, while additional frozen 2% cases show another
retention mechanism in other classes. The negative compression result and the
succinct symbolic example also prevent an unsupported storage claim. These are
specific advances over the current paper's selected query demonstration.

A new campaign could still answer a distinct prospective breadth question:
whether independently chosen, previously unobserved catalogues contain a
certified order-at-least-three obstruction under a frozen primary contract.
That would be new evidence, but the present audit neither requires it to
establish the stated claims nor supplies a quantified expectation that it
would materially strengthen them. Existing 2% successes cannot be reused as
outcome-blind catalogue selection. Searching merely for a second or larger
obstruction would not meet the stated rationale.

If a later research decision makes that prospective question a priority, a
separate frozen selection/protocol must precede confirmation responses,
including at least four metadata-chosen catalogues, the complete target
universe, fresh disjoint seeds, fixed sample size, comparison-family coverage,
and preserved YES/NO/UNKNOWN and negative results. This conditional description
does not authorize execution now or create a pending confirmation request.
